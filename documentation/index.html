Nexora Real Estate

HTML template · Version 1.1.0 · Updated October 2026

Introduction

Nexora is a responsive real estate website template built with semantic HTML5, CSS3 and vanilla JavaScript. It needs no build step, no jQuery and no framework. Open index.html in a browser, or upload the folder to any static host.

Features

  • Two homepage layouts (index.html, index-2.html) and 16 pages in total
  • Property search on the home page and filters, sorting, pagination and grid/list view on the listings page
  • Property details with photo gallery, fullscreen viewer, location map, mortgage calculator, enquiry form and similar listings
  • Agent list and profile pages, blog list (with categories) and article pages
  • Favorites saved in the visitor's browser
  • List-your-property form, contact form with map, FAQ, privacy, terms and 404 pages
  • Accessible form validation, keyboard-friendly navigation and gallery, skip link, visible focus states
  • Three colour themes (gold, blue, green) switched by a single attribute
  • Self-hosted fonts, icons and map library: no external CSS or font requests

Quick start

  1. Unzip the download. The template lives in the Nexora-Real-Estate folder.
  2. Open index.html in a modern browser, or serve the folder with any static server, for example npx serve or python3 -m http.server.
  3. Edit assets/js/data.js to add your properties, agents and articles.
  4. Replace the images in assets/images/ with your own photos.
  5. Change the brand colours at the top of assets/css/styles.css.
  6. Connect the forms to your own backend (see Forms).
The map tiles are loaded from OpenStreetMap, so maps need an internet connection. Everything else works offline.

Editing content

All listings, agents and posts live in assets/js/data.js inside the NexoraData object.

Properties

FieldDescription
idUnique number. Used in the page address, e.g. property-details.html?id=3
title, descriptionText shown on cards and the detail page
status"Sale" or "Rent" (rent prices show "/ month")
typeApartment, Villa, House, Commercial or Land
price, area, beds, baths, yearNumbers. Use 0 beds/baths for land or commercial
location, addressCity/state for search; street address for the detail page
lat, lngMap coordinates for the detail page
image, imagesCard image and an array of gallery images
featuredtrue to show on the home pages
agentIdThe id of an agent
amenitiesArray of short text strings

Adding a property

{
  id: 13, title: "Lakeside Cottage", type: "House", status: "Sale", price: 390000,
  location: "Portland, OR", address: "8 Lake Road", lat: 45.5152, lng: -122.6784,
  beds: 2, baths: 1, area: 1400, year: 2021, featured: false, agentId: 3,
  image: "assets/images/cottage-1.jpg",
  images: ["assets/images/cottage-1.jpg", "assets/images/cottage-2.jpg"],
  description: "A short description.",
  amenities: ["Garden", "Fireplace"]
}

Agents use id, name, role, location, email, phone, image, bio, specialties. Posts use id, title, date (YYYY-MM-DD), category, image, excerpt, body (array of paragraphs).

The property, agent and article pages are built in the browser from this file. For a large site, consider generating static pages or loading data from your own API: replace NexoraData with the result of a fetch() call.

Colors, fonts and logo

Colors

All colours are CSS variables at the top of styles.css:

:root {
  --ink: #15212b;           /* text and dark surfaces */
  --accent: #b8873a;        /* decorative accent */
  --accent-strong: #8a6120; /* buttons and links (AA contrast on white) */
  --cream: #f7f3ec;         /* soft section background */
}

Built-in themes: add data-theme="blue" or data-theme="green" to the <html> tag of each page. When choosing your own accent, keep --accent-strong dark enough for white text (contrast of at least 4.5:1).

Fonts

DM Sans (body) and Playfair Display (headings) are included as WOFF2 files in assets/fonts/ and declared with @font-face at the top of styles.css. To change fonts, add your font files, update the @font-face rules and set --font-body and --font-head.

Logo

The logo is a text wordmark plus an icon inside <a class="logo"> in each page's header and footer. Replace its contents with an <img> tag if you have a logo file.

Forms

Forms marked with data-validate are validated in the browser: required fields, email, phone, number ranges and minimum length, with accessible error messages. A hidden honeypot field catches simple bots.

The template contains no server code. On a valid submit the demo shows a success message. To send the data somewhere, add a handler in main.js inside bindForms, just before the success message, for example with a form service such as Formspree:

fetch('https://formspree.io/f/your-form-id', {
  method: 'POST',
  headers: { 'Accept': 'application/json' },
  body: new FormData(form)
}).then(function (response) {
  if (!response.ok) { throw new Error('Request failed'); }
  /* show the success message here */
}).catch(function () {
  /* show an error message here */
});

You can use Netlify Forms, your own PHP/Node endpoint or a CRM in the same way. Remember to add server-side validation and spam protection.

Maps

Maps use Leaflet (included in assets/vendor/leaflet/) with OpenStreetMap tiles. Property maps use the lat and lng values from data.js; the office map is set in assets/js/pages/contact.js. Keep the OpenStreetMap attribution visible.

OpenStreetMap's public tile server is intended for light use. For a busy production site, use a commercial tile provider and change the URL in Nexora.initMap inside main.js.

Favorites

Saved property ids are stored in the browser's localStorage under nexoraFavorites. This is a convenience feature, not an account system. If storage is blocked, favorites still work until the page is closed.

Accessibility and SEO

  • Skip link, landmark regions, labelled forms and a single h1 per page
  • Visible focus outlines, keyboard-operable gallery, menu and dialogs (Escape closes, arrows move through photos)
  • Colour pairs chosen for WCAG AA contrast; animations are reduced when the visitor prefers reduced motion
  • Unique title and meta description on each page; Open Graph tags are included

Before launch, add a canonical URL, an Open Graph image (1200 × 630 px PNG or JPG), a sitemap and structured data suited to your business.

Browser support

Latest two versions of Chrome, Edge, Firefox and Safari (desktop, iOS and Android). Internet Explorer is not supported. Tested at widths from 360 px to 1920 px.
